# 런타임 비교

[English](runtime-comparison.md) · [한국어](runtime-comparison.ko.md) · [벤치마크 목록](README.ko.md)

## 합성 / 서빙 디코딩 처리량

단위: tok/s(초당 토큰 수).

| 런타임 | 짧은 입력 | 32K 표기 | 80K 표기 | 114K 표기 |
| --- | ---: | ---: | ---: | ---: |
| SGLang NVFP4 | 약 69.3 | 미측정 | 약 60.8 | 미측정 |
| Q5_K_M llama.cpp MTP3 | 151.72 | 120.29 | 98.59 | 94.66 |
| NInfer NVFP4 + FP8 KV + MTP3 | **222.0** | **190.6** | **176.9** | **169.8** |

SGLang 80K+ 값은 집계 대상 장기 실행의 로그 표본 43개에서 구한 중앙값 60.77 tok/s를 60.8로 반올림한 값입니다. 정상 상태 디코딩 중앙값은 69.325 tok/s로, 69.3으로 반올림했습니다.

NInfer 행은 2026-09-09 로컬 depth 측정입니다. 기존 32K / 80K / 114K 표기에 대응하는 실제 프롬프트 크기는 **38,717 / 83,917 / 113,956토큰**입니다. NInfer 짧은 입력은 54토큰으로 과거 Q5 짧은 입력과 조건이 같지 않습니다. 모델 파일, 채팅 템플릿, API, 캐시 구현도 다르므로 런타임 자체의 순수한 차이로 귀속할 수 없습니다. 따라서 이는 같은 시점의 완전한 A/B가 아니라 과거 측정과의 비교입니다.

장문 구간에서 NInfer의 측정 디코딩 속도는 과거 Q5 값 대비 약 **1.58배 / 1.79배 / 1.79배**였습니다. NInfer depth 측정 12회는 출력 3,600토큰을 생성했고, MTP 제안 3,243개 중 2,502개가 수락되어 전체 수락률은 **77.15%**였습니다.

## NInfer 약 94K Codex 제한 작업 — 어댑터 수정 후 재검증

실제 Codex CLI 작업에는 84K 참조 컨텍스트와 일반 지침/도구가 함께 들어가 약 94K 프롬프트가 생성되었습니다. 최초 실행은 Responses 호환 계층이 지원하지 않는 `internal_chat_message_metadata_passthrough`를 전달하면서 실패했습니다. 이후 NInfer 전용 어댑터가 해당 메타데이터만 제거하고 도구 인자, 출력, call ID, 메시지 내용은 보존하도록 수정했습니다.

같은 읽기 → 수정 → 테스트 작업을 다시 실행한 결과:

| 지표 | 관측값 |
| --- | ---: |
| Codex 종료 코드 / 실제 경과 시간 | 0 / **33.409초** |
| 성공한 도구 실행 | 2회 (읽기; 수정 + 테스트) |
| API 생성 요청 | 3회 |
| 요청별 프롬프트 토큰 | 94,338 / 94,544 / 94,682 |

각 생성은 출력 48 / 79 / 120토큰에 불과합니다. 이 결과는 어댑터 수정 후 제한된 실제 도구 경로와 작업 완료를 검증하는 증거이며, 대표적인 장기 에이전트 평균 TPS로 보지 않습니다.

## 에이전트 실행 기록

### NInfer NVFP4 + MTP3
- **약 94K Codex 제한 검증:** 최초 Responses 호환성 실패를 보존했고, 수정 후 재실행은 read/edit/test 및 독립 테스트 3/3 PASS.
- **장기 자율 실행:** 아직 검증되지 않음.
- 공개된 222.0 / 190.6 / 176.9 / 169.8 tok/s는 런타임 depth 디코딩 측정이며 자율 에이전트 평균값이 아닙니다.

### SGLang NVFP4
- 집계 대상: 중간 규모 웹 프로젝트 실행 1회
- 실제 경과 시간: 526.388초
- 도구 호출: 86회
- 타입 검사, 린트, 테스트 8/8, 빌드, `git diff --check`: 통과
- 주요 데스크톱·모바일 브라우저 흐름: 통과
- 최종 판정: 실패. 허용되지 않은 생성된 shadcn 파일 수정 1건과 모바일 Sheet 포커스 복원 누락이 원인입니다.

### Q5_K_M MTP3
- **제한된 코딩 검증:** TSX 픽스처 10/10, 여러 파일의 빌드·테스트 2/2 통과.
- **과거 실행:** 루프 감시가 없던 집계 대상 실행 1회에서, 541초 동안 의미 있는 수정이 없었습니다. 과도하게 큰 정규식 생성에 32,768토큰을 소비했습니다.
- **재검증(2026-08-19):** `skipLoopDetection: true`와 외부 의미적 진행 감시를 적용해 긴 자율 구현을 수행했습니다. 대상은 `App.tsx`, `data.ts`, `index.css`, `App.test.tsx`, `test-setup.ts`의 총 1,026줄입니다.
  - `typecheck`: PASS, 오류 0
  - `lint`: PASS, 오류 0
  - `vitest`: 12/12 PASS (100%)
  - `build`: PASS (313 ms)
  - `git diff --check`: PASS, 오류 0
  - 이 실행에서는 비교 가능한 전체 작업 소요 시간을 수집하지 않았습니다.

## 해석

최신 공개 로컬 측정으로 raw throughput 해석은 바뀌었습니다. **현재 depth 측정에서 가장 빠른 디코딩 경로는 NInfer**이며, 실제 프롬프트 113,956토큰에서도 169.8 tok/s를 기록했습니다. 그렇다고 아직 기본 에이전트 런타임으로 승격한 것은 아닙니다.

Q5_K_M + llama.cpp + MTP3는 100K+ 자율 코딩 궤적에서 평균 109.51 tok/s, MTP 수락률 89.61%, 실행 후 typecheck/lint/build/vitest 통과라는 가장 강한 장기 자율 검증 증거를 갖고 있어 기본값을 유지합니다. NInfer는 어댑터 수정 후 약 94K 실제 Codex 도구 경로를 통과했지만, 동일 수준의 장기 자율 검증은 아직 없습니다.

따라서 raw decode TPS, 제한 작업의 실제 경과 시간, 장기 에이전트 처리량을 하나의 순위로 합치지 않고 각각 분리해 보고합니다.

원시 측정값, 프롬프트 해시, 최초 실패 보존, 어댑터 수정 후 재검증은 [NInfer 검증 문서](ninfer-qualification-2026-09-09.ko.md)를 참고하세요.
