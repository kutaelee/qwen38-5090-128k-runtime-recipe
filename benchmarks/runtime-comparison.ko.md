## 합성 / 서빙 디코딩 처리량

단위: tok/s(초당 토큰 수).

| 런타임 | 짧은 입력 | 32K 표기 | 80K 표기 | 114K 표기 |
| --- | ---: | ---: | ---: | ---: |
| SGLang NVFP4 | 약 69.3 | 미측정 | 약 60.8 | 미측정 |
| Q5_K_M llama.cpp MTP3 | 151.72 | 120.29 | 98.59 | 94.66 |
| NInfer NVFP4 + FP8 KV + MTP3 | **222.0** | **190.6** | **176.9** | **169.8** |

SGLang 80K+ 값은 집계 대상 장기 실행의 로그 표본 43개에서 구한 중앙값 60.77 tok/s를 60.8로 반올림한 값입니다. 정상 상태 디코딩 중앙값은 69.325 tok/s로, 69.3으로 반올림했습니다.

NInfer 행은 2026-09-09 로컬 depth 측정입니다. 기존 32K / 80K / 114K 표기에 대응하는 실제 프롬프트 크기는 **38,717 / 83,917 / 113,956토큰**입니다. NInfer 짧은 입력은 54토큰으로 과거 Q5 짧은 입력과 조건이 같지 않습니다. 모델 파일, 채팅 템플릿, API, 캐시 구현도 다르므로 런타임 자체의 순수한 차이로 귀속할 수 없습니다. 따라서 이는 같은 시점의 완전한 A/B가 아니라 과거 측정과의 비교입니다.

장문 구간에서 NInfer의 측정 디코딩 속도는 과거 Q5 값 대비 약 **1.58배 / 1.79배 / 1.79배**였습니다. NInfer depth 측정 12회는 출력 3,600토큰을 생성했고, MTP 제안 3,243개 중 2,502개가 수락되어 전체 수락률은 **77.15%**였습니다.

NInfer 장기 에이전트 작업도 이전 로컬 사용에서 정상 완료된 사례가 있습니다. 다만 해당 과거 성공 실행은 이 저장소에 비교 가능한 계측 묶음으로 보존돼 있지 않으므로, 존재하지 않는 정량 수치를 소급해 표에 채우지 않습니다.

## NInfer 장기 에이전트 실시간 계측 — 2026-09-16

현재 계측 실행이 진행 중인 시점의 스냅샷입니다.

| 지표 | 실시간 스냅샷 |
| --- | ---: |
| 완료 요청 수 | **101** |
| 생성 출력 토큰 | **96,241** |
| Aggregate decode throughput | **132.23 tok/s** |
| 요청별 decode 평균 | **140.59 tok/s** |
| 요청별 decode 중앙값 | **136.2 tok/s** |
| 전체 MTP 수락률 | **51.71%** |
| 표시된 로그에서 확인한 프롬프트 깊이 | **최소 88,250토큰** |
| 현재 작업 최종 판정 | 실행 중이라 미확정 |

`Aggregate decode throughput`은 각 완료 요청의 `output_tokens / request_decode_tps`로 추정한 디코딩 시간을 합산한 뒤 전체 출력 토큰을 나눈 출력 토큰 가중값입니다. 짧은 요청과 수천 토큰짜리 요청에 같은 가중치를 주는 단순 평균보다 이 실행의 대표값으로 적합합니다.

같은 로그 구간에는 79K~88K 프롬프트에서 5,556 output / 130.6 tok/s, 3,454 output / 130.5 tok/s 같은 긴 생성이 포함되어 있습니다. 따라서 132.23 tok/s aggregate 값이 짧은 synthetic completion만으로 만들어진 값은 아닙니다.

현재 **132.23 tok/s**는 과거 Q5 장기 실행의 **109.51 tok/s**보다 수치상 약 **20.7% 높지만**, workload·하니스·요청 분포·MTP 수락률이 같은 동시 A/B가 아니므로 런타임 자체가 20.7% 빠르다고 단정하지 않습니다.

상세 스냅샷과 완료 후 갱신 항목: [ninfer-long-agent-live-2026-09-16.md](ninfer-long-agent-live-2026-09-16.md).

## NInfer 약 94K Codex 제한 작업 — 어댑터 수정 후 재검증

실제 Codex CLI 작업에는 84K 참조 컨텍스트와 일반 지침/도구가 함께 들어가 약 94K 프롬프트가 생성되었습니다. 최초 실행은 Responses 호환 계층이 지원하지 않는 `internal_chat_message_metadata_passthrough`를 전달하면서 실패했습니다. 이후 NInfer 전용 어댑터가 해당 메타데이터만 제거하고 도구 인자, 출력, call ID, 메시지 내용은 보존하도록 수정했습니다.

같은 읽기 → 수정 → 테스트 작업을 다시 실행한 결과:

| 지표 | 관측값 |

| 성공한 도구 실행 | 2회 (읽기; 수정 + 테스트) |

각 생성은 출력 48 / 79 / 120토큰에 불과합니다. 이 결과는 어댑터 수정 후 제한된 실제 도구 경로와 작업 완료를 검증하는 증거이며, 대표적인 장기 에이전트 평균 TPS로 보지 않습니다.

- **장기 실사용:** 이전 로컬 장기 에이전트 작업들이 정상 완료됨.
- **계측 중 장기 실행(2026-09-16):** 스냅샷 시점 101 requests / 96,241 output tokens / 132.23 tok/s aggregate decode / MTP 51.71%; 현재 실행 최종 acceptance는 당시 진행 중이라 미확정.
- 공개된 222.0 / 190.6 / 176.9 / 169.8 tok/s는 runtime depth 디코딩 측정이며 실사용 장기 aggregate와 분리해 보고합니다.

## 해석

최신 로컬 측정에서 **NInfer가 depth probe 기준 가장 빠른 디코딩 경로**이며, 실제 프롬프트 113,956토큰에서도 169.8 tok/s를 기록했습니다. 장기 에이전트 작업도 이전 로컬 사용에서 성공했고, 새 계측 실사용 스냅샷에서는 **96,241 output tokens 동안 132.23 tok/s aggregate decode**를 기록하며 실행 중이었습니다.

Q5_K_M + llama.cpp + MTP3는 완료된 100K+ 자율 작업의 acceptance 묶음이 저장소에 가장 완전하게 남아 있기 때문에 보수적 기본값을 유지합니다. 이는 NInfer가 장기 작업을 완료하지 못한다는 의미가 아니라 **증거 보존 수준의 차이**입니다.

따라서 raw depth TPS, 제한 작업 wall time, 실사용 장기 aggregate decode, 최종 작업 acceptance를 하나의 순위로 합치지 않고 각각 분리해 보고합니다.

원시 depth 측정과 bounded Codex 실패/수정 기록은 [NInfer 검증 문서](ninfer-qualification-2026-09-09.ko.md), 현재 장기 실사용 스냅샷은 [NInfer live telemetry](ninfer-long-agent-live-2026-09-16.md)를 참고하세요.
